## 3. Hybrid Strategy Transition (OPTIMIZE LATER)
Currently, data lives in both Dexie (local) and PostgreSQL (cloud). Once cloud stability is 100% verified over a few months:

### Professional Invoices (Frontend)
- **Local DB Schema**: Fields like `syncStatus`, `lastSyncedAt`, and `userId` in `src/lib/db.ts` can be reconsidered if the app moves to a direct-to-cloud model.
- **SyncManager**: The background polling logic in `src/lib/sync-manager.ts` can be replaced with WebSockets or Realtime (Supabase) for lower latency and better battery efficiency.
- **Initial Upload Logic**: The `uploadInitialData` function in `SyncManager` is only needed for migrating legacy local users. It can be removed once all active users are on the cloud.

### Gummadii (Backend)
- **JWT Rotation**: `JWT_SECRET` in `.env` is currently static. Implement rotation or use a more robust OAuth provider (like Supabase Auth directly) to reduce backend maintenance.
- **Database Indexing**: Add indexes on `user_id` columns in all tables if performance degrades as the user base grows.
